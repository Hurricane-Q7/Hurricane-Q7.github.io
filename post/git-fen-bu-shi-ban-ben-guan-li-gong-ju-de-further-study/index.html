Git-分布式版本管理工具的Further Study!

2026-03-24 8 min read # git学习

Git分区思想🌟🌟🌟🌟🌟

1. 工作区：你现在正在干什么
2. 暂存区：你准备提交什么
**Git 设置暂存区的最大价值，就是让你能够“选择并组织本次提交的内容”，而不是把工作区所有修改一股脑提交到仓库。 这也是 Git 比很多早期版本控制工具更灵活的重要原因。**
3.   仓库：你以前干过什么（提交过哪些？）

Git操作的基本Workflow

Git基础操作（add/commit/status/log/diff/reset）

HEAD是git中一个很重要的概念

 HEAD 本身通常指向当前分支，而不是直接指向当前版本（提交）。
 当然HEAD也可以简单记为当前地版本号。

指令速查：

git基础必会内容：
git init 在本地创建一个git repository.
git status //常看文件状态
git add和git commit//把文件添加到暂存区，把暂存区的文件添加到git仓库
git log //查看提交记录、日期、提交人、commitID
git diff //查看变化
.gitignore //git的忽略配置文件
git reset

git status 查看文件修改的状态：

  • 作用：查看当前文件的修改状态
  • 格式：git status
  • 常见状态：
    modified（已跟踪文件被修改）
    Untracked files（Git根本不认识的新文件）
1. untracked（新添加的文件）
2. unstaged  （未进入暂存区）
3. to be commited(在暂存区里等待提交）
在工作区里面添加文件后，不代表git认识这个文件，因为此时你还没有用git跟踪一下，此时用git status看一下，显示Untracked状态，说明此时git不认识这个文件，这时候最好git add 文件一下，告诉git。

git log查看commit日志：

  • 作用：查看提交记录，与commitID
  • 格式：git log [options]
  •       --all显示所有分支

  •       --pretty=oneline将提交信息显示为一行

  •       --abbrev-commit 使得输出的commit更简短

  •       --graph 以图的形式显示 
     以上参数可以组合起来使用。

git commit-提交指令：

  • 作用：将文件或目录提交到本地仓库，提交后会形成历史记录（暂存区->本地仓库）
  • 格式：git commit -m "提交信息"
    git add 指令：
  • 作用：将文件或目录添加到从工作区到暂存区
  • 格式：git add 文件名/git add .（全部提交）
    git diff 查看文件修改情况::🌟🌟🌟

- 作用：查看文件变更内容
- 核心思想：git diff指令地作用就是比较不同状态下的文件的差异
常见指令: 
1. git diff 文件名 （对比工作区和暂存区）
2. git diff --cached 文件名(对比暂存区和仓库)
3. git diff A  B(A和B可以是版本ID也可以是两个不同的分支)
4. git diff --stat:
git diff --stat 就是“代码改动统计表”，用于快速查看哪些文件发生了变化，以及变化规模，而不显示具体代码内容。
5. git diff --HEAD :比较工作区和仓库的变化。
6. git diff HEAD~ HEAD:比较当前指向版本和上一个版本地差异（HEAD~用来表示上一个版本，HEAD~2 表示上两个版本）

git restore 修复改动指令

- 作用：修复改动
- 命令形式：git restore --staged/git restore 文件名
git restore --staged 文件名可以把暂存区的文件直接拉到工作区，取消暂存区。
git restore 文件名，可以撤销在工作区里面的修改，但是前提必须是git要认识这个文件，想要让git认识这个文件，就要先add一下。

git reset --hard 版本回退（非常重要）：

- 作用： 切换版本
- 命令形式：git reset --hard commitID
--hard参数有啥意义？
--hard会回退到上个版本的已提交状态(commit后)，
而--soft会回退到上个版本的未提交状态（已经add后），
--mixed会回退到上个版本已添加但未提交的状态。现在，先放心使用--hard。

git reset Git 的 HEAD（当前版本指针）回到之前的某个位置，并根据参数决定是否同时修改暂存区和工作区。

git reset比起git restore更加关注历史提交记录。
- 作用：版本回退
- 命令形式：git reset --soft/--mixed/--hard COMMITID

git reflog - 查看已经删除的记录

  • git reflog
  • 这个指令可以看到已经删除的提交记录（commit ID）

Git的忽略配置文件.gitignore🌟🌟🌟🌟🌟

功能介绍：
这个功能需要我们写一个配置文件来实现，这个配置文件的名字叫做**.gitignore**，我们可以把我们当前目录下面不想要暂存、提交、上传的文件或目录的名字写进这个配置文件，这样就git记下来了。
使用示例(vs的项目目录下)：
一般用vs创建的项目目录下有很多东西，为了让自己的仓库变干净一点，项目里面有的东西我们可以过滤掉，这样在执行git add/git commit等命令时就不会把它们也移动git工作区域了。

添加并修改.gitignore配置文件

.vs/
Git_test.slnx
Git_test.vcxproj
Git_test.vcxproj.filters
Git_test.vcxproj.user
# 添加完这些后，在使用git add 后，它们就不会在暂存区里面了，然后就可以大胆的commit了。

Git核心操作-分支管理🌟🌟🌟🌟🌟🌟

Head指向谁，就说明当前在哪个分支上
分支是Git中的一个很重要的概念！

关于分支的常见命令

1. git branch //查看所有分支
2. git branch 分支名称 //创建分支
3. git checkout 分支名称 //切换到分支
4. git checkout -b 分支名称 //创建并切换到该分支
5. git branch -d 分支名称 //删除强制删除是 -D
6. git branch -m 当前分支name 分支名称//修改当前分支名称
7. git merge 分支1 //假如当前是分支0，这条指令的意思是把分支1和并到分支0上

使用Git中的merge指令时可能遇到的问题

在当前分支下先创建一个分支，在这两个分支上同时修改共有文件，分别进行add/commit指令，最后切换到原分支，使用git merge 新创建的分支，此时会发现冲突！

解决方法：

  1. 暴力修改，直接修改文件内容
  2. add / commit 双板斧

开发中分支的使用原则与流程


Git和远程仓库！！！

使用git可以把本地仓库里面的代码统统推送到远程仓库上！

基本步骤：
1. 绑定链接关系
git remote add <远程仓库名> <远程仓库地址https/ssh>
2. 查看远程仓库
git remote 
3. 推送代码
命令：git push [-f] [--set-upstream] [远端名称[本地分支名][:远端分支名]]
如果远程分支和本地分支名称相同，则可以只写本地分支！
- [-f] 强制推送
- git push origin master 
-- set-upstream 推送到远端的同时并且建立起和远端分支的关联关系
- git push --set-stream origin master
如果当前分支和远端分支关联，则可以省略分支名和远端名
- git push 将master 分支推送到已关联的远端分支

Git clone

命令：git clone <仓库链接> <别名>
作用：把远程仓库里面的内容全部拉到本地指定路径里面！
注意：git clone这个指令一般只用来第一次拉取代码，后续一般是git pull！

从远程仓库抓取和拉取

远程分支和本地的分支一样，我们可以进行merge操作，只需要先把远端仓库里的更新都下载到本地，在进行操作。

  • 抓取命令：git fetch [remote name][fetch name]
    • 抓取指令就是将仓库里的更新都抓取到本地，不会进行合并（merge）
    • 如果不指定远端名和分支名，则抓取所有分支。
  • 拉取命令：git pull [remote name][branch name]
    • 拉取指令就是将远端仓库的修改拉到本地并自动进行合并，等同于fetch+merge
    • 如果不指定远端名和分支名，则抓取所有分支。
